# v0.1 scope

v0.1 is a small My Tasks-first vertical slice for one human user and autonomous
agents. It must complete the common workflows reliably before the broader
product specification is implemented.

The CLI is not implemented yet. This document is the implementation boundary
for the first release.

## Required workflows

### Read a task and its comments

```sh
asana-cli tasks get <task_gid>
asana-cli tasks comments <task_gid>
```

`tasks get` returns `notes` by default because reading the assignment is the
primary single-task workflow. `tasks comments` filters the Asana Stories feed
to comment stories.

### Replace a task description

```sh
asana-cli tasks update <task_gid> --notes="Replacement text"
asana-cli tasks update <task_gid> --notes-file=description.md
generate-description | asana-cli tasks update <task_gid> --notes-file=-
```

`--notes` and `--notes-file` are mutually exclusive. Notes are replaced
explicitly; v0.1 has no read-modify-write append operation.

### Move a task in My Tasks and comment

```sh
asana-cli tasks update <task_gid> --my-section=@in_review
asana-cli tasks comment <task_gid> "Ready for review"
review-agent | asana-cli tasks comment <task_gid> --file=-
```

v0.1 manages personal My Tasks sections only. Shared project sections are
deferred.

### Create an estimated subtask assigned to the current user

```sh
asana-cli tasks create \
  --parent=<task_gid> \
  --name="Implement the change" \
  --assignee=me \
  --my-section=@in_progress \
  --custom-field=@hours_estimate:4
```

The operation validates every resolvable input before its first write, then
creates the subtask and applies My Tasks-specific values in dependency order.
It is not transactional. A failure after subtask creation returns a staged
partial result and exit code 1.

## Commands

```text
asana-cli whoami

asana-cli config init --shared --workspace=<gid>
asana-cli config init --local [--write-gitignore]
asana-cli config get <key> [--source]
asana-cli config set <key> <value> [--shared|--local|--global]
asana-cli config show [--json] [--sources]
asana-cli config resolve my-tasks

asana-cli tasks get <id>
asana-cli tasks update <id> <mutation flags...>
asana-cli tasks create --parent=<id> --name=<name> <mutation flags...>
asana-cli tasks comments <id> [pagination flags...]
asana-cli tasks comment <id> <text>
asana-cli tasks comment <id> --file=<path|->
```

Global flags:

```text
--help, -h
--version, -v
--json
--fields=<asana-fields>
--debug
```

Global flags work before or after a subcommand. Capability validation rejects
unsupported flag-command combinations with exit code 2.

## Authentication

v0.1 requires `ASANA_CLI_TOKEN`. There are no `login`, `logout`, keychain,
`.env`, or shell-profile mutation features.

## Configuration

Required shared configuration:

```json
{
  "workspace": {
    "gid": "1201947864389005"
  }
}
```

Personal local configuration:

```json
{
  "myTasks": {
    "userTaskListGid": "1213894072990299",
    "sections": {
      "in_progress": "1213894072991394",
      "in_review": "1213894072991395",
      "done": "1213894072991396"
    },
    "customFields": {
      "hours_estimate": "1213894072991499"
    }
  }
}
```

`config init --local` resolves the authenticated user's task list in the
configured workspace and imports both section and custom-field aliases. Alias
generation lowercases a name, replaces each run of non-letter/digit characters
with `_`, and trims leading/trailing `_`. Unicode letters and digits remain.
Collisions fail before writing.

The local file must already be ignored or initialization requires
`--write-gitignore`. The CLI adds exactly `/.asana-cli.local.json` to the
nearest repository `.gitignore`.

Named profiles and schema versioning are deferred.

## Task values

Task IDs accept raw digit-only GIDs and the documented unambiguous Asana task
URLs.

v0.1 mutation flags:

```text
--name=<text>
--notes=<text>
--notes-file=<path|->
--assignee=me|<user-gid>|null
--due-on=YYYY-MM-DD|null
--completed=true|false
--parent=<task-id>
--my-section=<section-gid>|@<alias>
--custom-field=(<field-gid>|@<alias>):<value>
```

`--custom-field` is repeatable. v0.1 writes only number custom fields. It
accepts finite integers or dot-decimal numbers and `null`; enum, multi-enum,
text, date, people, and reference fields are deferred. Before writing, the CLI
live-validates the field definition against My Tasks.

`--assignee` does not resolve email addresses in v0.1. A command with
`--my-section` validates before writing that the final assignee is the
authenticated user.

`tasks create` creates only subtasks in v0.1, so both `--parent` and `--name`
are required. Top-level creation is deferred with shared project support.

## Reads and output

Default `tasks get` fields:

```text
gid
name
notes
completed
due_on
assignee.gid
assignee.name
```

`tasks comments` returns at most 20 comments by default while scanning at most
100 stories. `--max=<n>` changes the scan cap. `--all` requires `--max`.
`--offset` starts from a known Asana offset. The result preserves API order and
does not claim to be newest-first. Reaching the scan cap sets
`meta.scan_truncated=true`.

Default comment fields:

```text
gid
created_at
text
created_by.gid
created_by.name
```

Collections use a borderless table; single resources use key/value detail
output with multiline blocks. v0.1 has no color. JSON uses the stable
`{ "data": ..., "meta": ... }` envelope.

## Reliability

- 30-second request timeout.
- Concurrency defaults to 4.
- Maximum retries default to 3.
- GET, PUT, and DELETE retry network errors, 429, 502, 503, and 504.
- POST retries only an explicit 429 response.
- `Retry-After` takes precedence over exponential backoff with jitter.
- A POST is never retried after an ambiguous timeout, network error, or 5xx.
- Multi-step commands return every completed and failed stage.

Exit codes:

```text
0 success
1 partial write or stage failure
2 invalid usage or configuration
3 authentication or authorization failure
4 Asana API error or not found
5 rate-limit or retry exhaustion
6 unexpected internal CLI error
```
